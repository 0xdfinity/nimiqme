How it works

Two loops. One payment rail.

The buyer side is a single conversation. The merchant side is a CSV and a link. Both end at the same verified NIM transaction.

Buyer loop

from request to receipt
1. AskType what you want in plain language, with a budget if you have one.
2. BuildThe agent assembles a cart from storefronts and shows one total.
3. ApproveOne tap in Nimiq Pay signs the exact quoted amount in NIM.
4. ReceiptThe order is checked on the explorer, then the receipt and order status update.

Merchant loop

from CSV to orders
1. UploadDrop in a 5-field CSV with name, price, image URL, description and stock.
2. CheckInvalid rows are flagged with their line numbers before anything is saved.
3. LinkEach product gets a payable link you can share or place on a page.
4. TrackVerified payments land in the orders dashboard as they settle.
What the agent does

It does the tedious part. You keep the decision.

The agent searches, compares and assembles. It never moves money on its own. Each payment waits for your approval of one exact total.

Search

Reads your request

Turns a sentence like "a gift under 40 NIM" into a product search across the storefronts it can reach, with budget and category applied.

Build

Assembles one cart

Finds the item, sums the price with delivery, and shows the exact total before you approve.

Verify

Confirms before "paid"

After your approval the transaction is checked on the Nimiq explorer. Until every check passes, the order is not shown as paid.

Tech stack

Built on Nimiq Pay, fail-closed by design.

The parts that touch money are deliberately small and checkable. Anything uncertain is reported as unconfirmed, never as paid.

Nimiq Pay mini app SDK

The app runs inside Nimiq Pay and uses the mini app SDK to read the account and send a single NIM transaction with the order reference.

  • Package: @nimiq/mini-app-sdk
  • No private keys in the app

NIM payment rail

Checkout binds to one quoted total. If the cart changes after quoting, the approval is voided instead of quietly re-priced.

  • Explorer confirmation before "paid"
  • Hash, recipient, amount and order reference all checked

Fail-closed AI gateway

The model only rewords answers. Prices and totals come from the catalog and the rule engine, so the app stays correct with no model connected.

  • Primary and fallback model routes
  • Off by default when no key is set
